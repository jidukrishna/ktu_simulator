⚛️ Module 3 — Client-Side Framework (React)
Q1APPLIED
In an MVC-based e-commerce app, a user updates their shipping address on a form. Which component is responsible for validating the new address and instructing the database to save it?
  • AView
  • BController
  • CModel
  • DRouter
Answer: Controller. The Controller receives user input from the View, validates/processes it, and instructs the Model to update the database. The Model itself just performs the actual CRUD operation once told to.
Q2HARD
Why is the Presentational/Container pattern considered less necessary in modern React codebases?
  • ABecause React no longer supports props
  • BBecause class components were removed from React
  • CBecause Custom Hooks let you extract "container" logic without needing a wrapper component
  • DBecause Context API replaced all component rendering
Answer: Custom Hooks replace the need for wrapper "container" components. A hook like useFetch() can be called directly inside any functional component, achieving the same logic/UI separation without an extra layer of components.
Q3APPLIED
You want to add a "loading spinner" behavior to five completely unrelated components without duplicating code. Which pattern is the classic solution designed for exactly this?
  • AHigher-Order Component (HOC)
  • BMVC Pattern
  • CJSX
  • DConditional Rendering
Answer: Higher-Order Component (HOC). An HOC like withLoading(Component) wraps any component and injects shared behavior (like a spinner) without modifying the original component's code.
Q4HARD
What is the key difference between how an HOC and a Custom Hook share logic across components?
  • AThere is no difference — they are the same thing
  • BHOCs can only be used in class components; Custom Hooks only in HOCs
  • CCustom Hooks require a database connection; HOCs do not
  • DAn HOC wraps a component and returns a new component (adds a layer to the tree); a Custom Hook is just a function you call inside a component (no extra wrapper/nesting)
Answer: D. HOCs add an extra component layer ("wrapper hell" if overused), while custom hooks just inject logic directly into an existing component's function body — no extra nesting in the component tree.
Q5APPLIED
A large app has a "logged-in user" object needed by a top-level Navbar, a deeply nested Comment component, and a Footer. Passing it through 6 layers of props is painful. What's the best fix?
  • ADuplicate the user object in every component's own state
  • BWrap the app in a Context Provider and use useContext() in whichever component needs the data
  • CStore the user object only in the URL query string
  • DConvert every component into a class component
Answer: B — use Context API. This is the textbook fix for prop drilling: wrap the relevant part of the tree in a Provider, then any descendant can call useContext() directly.
Q6HARD
What will this code render on screen when count is 0?
function CartBadge({ count }) {
  return <div>{count && <span>{count} items</span>}</div>;
}
  • ANothing at all (empty div)
  • BThe literal number 0
  • C"0 items"
  • DA React error
Answer: B — the literal number 0 is rendered. This is a classic conditional-rendering pitfall: 0 is falsy, so the && expression short-circuits to 0 itself, and React renders that number. The fix is {count > 0 && ...}.
Q7APPLIED
You're converting a class component's componentDidMount + componentWillUnmount (which sets up and clears a setInterval timer) into a functional component. What is the correct useEffect setup?
  • AuseEffect(() => { setInterval(fn, 1000); }) with no dependency array
  • BuseEffect(() => { fn(); }, [fn])
  • CuseEffect(() => { const id = setInterval(fn, 1000); return () => clearInterval(id); }, [])
  • DFunctional components cannot use timers
Answer: C. The empty dependency array [] makes it run once (like componentDidMount), and returning a cleanup function that calls clearInterval replicates componentWillUnmount.
Q8HARD
Which statement about React props vs state is INCORRECT?
  • AProps are passed from parent to child and are read-only inside the child
  • BState is local to the component and can be changed using its setter function
  • CChanging state triggers a re-render of that component
  • DA child component can directly mutate the props object it receives to update the parent's data
Answer: D is incorrect (and thus the answer to find). Props are strictly read-only/immutable from the child's perspective — a child cannot mutate them to affect the parent. To change parent data, the parent must pass down a callback function as a prop.
Q9APPLIED
A component fetches user data whenever the route's :id parameter changes. What MUST be included in the useEffect dependency array to avoid stale data bugs?
  • Aid (the value read from useParams())
  • BNothing — leave the array empty
  • CThe entire component
  • DuseState
Answer: A — id. If id is omitted from the dependency array, the effect only runs once with the very first id, and the component will keep showing stale data even after the URL changes.
Q10APPLIED
Why might an installable, offline-capable news reader web app choose to be built as a PWA instead of a native app?

  • BPWAs avoid app store approval, work cross-platform from one codebase, and are lighter-weight while still supporting offline caching and installability
  • CPWAs require a native compiler for every OS

Answer: B. PWAs use Service Workers for offline caching and a Web Manifest for installability, all from a single cross-platform codebase, without App Store review delays.
Q11HARD
During reconciliation, React compares the new Virtual DOM tree against the previous one. What is the actual outcome of this comparison used for?
  • ATo recompile the entire application from scratch
  • BTo delete and recreate every DOM node on every render
  • CTo compute the minimal set of differences ("diffing") and apply only those specific changes to the real DOM

Answer: C. This diffing + minimal patching is exactly what makes React fast compared to manipulating the real DOM directly on every state change.
Q12APPLIED
You write a component named car() (lowercase) and use it as <car /> in JSX. What actually happens?

Q13APPLIED
Which of these is a genuine advantage of functional components over class components?

  • BOnly functional components can have state at all
  • CClass components cannot render JSX
  • DFunctional components run on the server only
Answer: A. Both component types can hold state today (via hooks or this.state), but functional components avoid `this`-binding issues and boilerplate, making them shorter and easier to test.
Q14HARD
A class component defines shouldComponentUpdate() and always returns false. What is the effect?
  • AThe component crashes immediately
  • BThe component mounts twice
  • CIt has no effect on rendering behavior
  • DThe component will never re-render again, even if its state or props change
Answer: D. shouldComponentUpdate is a performance-optimization hook in the Updating phase — returning false tells React to skip re-rendering entirely for that update.
Q15APPLIED
Which conditional rendering technique is most appropriate for a component that must render one of FOUR different views based on a "status" string (loading/error/empty/success)?
  • ATernary operator nested three times
  • BLogical AND (&&) chained four times
  • CA switch statement (or an inline function using if/else) — cleaner for many branches
  • DuseEffect
Answer: C. Ternary/&& work well for 1–2 conditions, but a switch statement (or a small render function with if/else) reads far more cleanly with 3+ branches.
Q16APPLIED
In the Context API pattern, what happens if a component calls useContext(MyContext) but is NOT nested inside the corresponding <MyContext.Provider>?
  • AReact throws a compile-time error and refuses to build
  • BIt receives the context's default value (or undefined if none was set) instead of the Provider's value

Q17HARD
Two custom hooks, useAuth() and useCart(), are both called inside the same component. Each internally calls useState. Do they share the same state?

Q20HARD
A PWA needs to show cached content when the user's phone loses internet mid-flight. Which single technology is fundamentally responsible for making that possible?

🖥️ Module 4 — Server-Side Web Development (Node.js / Express)
Q21HARD
What is the output order of this code?
console.log("A");
setTimeout(() => console.log("B"), 0);
Promise.resolve().then(() => console.log("C"));
console.log("D");
  • AA, D, C, B
  • BA, B, C, D
  • CA, D, B, C
  • DA, C, D, B
Answer: A, D, C, B. Synchronous code (A, D) always runs first. Then microtasks (Promise callbacks, C) run before the event loop moves to the Timers phase (setTimeout, B) — even with a 0ms delay.
Q22APPLIED
A Node.js REST API server needs to read a large 2GB log file on every incoming request to a specific route. Which choice avoids blocking all other clients?
  • Afs.readFileSync() inside the route handler
  • BReading the file once at server startup only, never per-request
  • Cfs.readFile() (async) or a readable stream, so the event loop isn't blocked while reading
  • DIt doesn't matter which method is used
Answer: C. Sync fs methods block Node's single thread, freezing every other request until the read finishes. Async methods or streams let the event loop keep serving other clients concurrently.

  • CThey run in random order depending on the OS
  • DNeither runs until all setTimeout callbacks finish
Answer: B. This ordering matters for writing predictable async code and is a favorite trick question distinguishing microtask priorities in Node.js.

Q26APPLIED

Q28APPLIED
A REST API always includes the full auth token in every request header instead of relying on server memory of "who's logged in." What REST principle does this exemplify?

Q31HARD
In a signup route, why must you use bcrypt.hash() instead of storing the raw password directly, given bcrypt is a one-way function?

Q44APPLIED
Which two pieces are combined (along with a secret key) to compute a JWT's HMACSHA256 signature?
  • AThe Base64Url-encoded header and the Base64Url-encoded payload
  • BThe username and password only
  • CTwo previous signatures
  • DThe client's IP address and timestamp
